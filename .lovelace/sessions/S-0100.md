## Approach

Session-scope the stop guard: helper commands read the hook payload Claude Code delivers on stdin, a new PostToolUse hook records each session's own active ticket in state/active/<session-id>, and session-check enforces only the stopping session's marker, falling back to the singleton when no payload exists. Scout mapped the machinery, programmer implemented, I audited, a fresh-context verifier attacked the built helper, and I closed its hardening findings myself.

## What happened

Core gained writeSessionActiveTicket/readSessionActiveTicket with a sanitised per-session marker under state/active; the helper gained readHookPayload and the track-active command; presence-clear clears the session marker on SessionEnd but not Stop; claude.ts registers the PostToolUse hook on set_active_ticket; SPEC.md section 12 documents the marker and the unreleased 3.1.0 changelog entry absorbed it. The singleton stays for the digest, app display and git commit-message injection. The verifier confirmed the acceptance criteria against the built helper (the exact original failure now resolves: session A passes while session B blocks on its own unrecorded ticket; all no-payload fallbacks byte-identical to the old messages) and refuted two hardening claims plus one informational: dot-only session ids passed the sanitiser and crashed session-check with EISDIR, a non-string tool_input.id wrote a garbage marker, and an unclosed stdin pipe could hang the hook. Fixed all three: the pattern now requires an alphanumeric so bare dots are refused, track-active acts only on the tool's two legal shapes (string sets, null clears), session-check fails open with a stderr note instead of ever trapping a stop, and the payload read times out after three seconds. All repros are regression tests. Full suite green (core 174, desktop 228, mcp 73), build green, sidecars rebuilt with the hardening confirmed in the agent binary, and this repository's own hook config regenerated through the install op so the new hook is live for future sessions.

## Open questions

- Orphan markers from crashed sessions accumulate harmlessly under state/active; add opportunistic pruning if it ever bothers anyone.
- Windows reserved device names (NUL, CON) pass the sanitiser and would silently no-op a marker there; hostile-only since real session ids are UUIDs.
- session-check now fails open on an unloadable project with a stderr note, which also softens the pre-existing helper-crash concern from S-0094 for this one command; digest and the other helper commands still lack a top-level catch.
