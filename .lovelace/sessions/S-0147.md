## What happened

ADR-0014 records the mapping: mcp.lovelace plus an instructions entry in opencode.json, a marker section in root AGENTS.md, commands in .opencode/commands, and the seven helper behaviours in a wholly Lovelace-owned plugin at .opencode/plugins/lovelace.js that adapts OpenCode payloads to the helper's Claude-shaped stdin (helper.ts unchanged). Three degradations named in the ADR because OpenCode cannot express them: digest is injected into the first user message per session (no session-start hook), session-check runs at session.idle and injects its reminder into the next message (no blocking stop), presence-clear is best effort on session.deleted with the ADR-0012 heartbeat bounding the rest. guard has full parity by throwing in tool.execute.before. Backend: new assets.ts with the shared machinery extracted from claude.ts (markers, JSON merge, agents template, git hook), claude.ts refactored onto it with claude.spec.ts passing without a single edit, new opencode.ts installer and detector, detect_opencode and install_opencode host ops, 21 new tests in opencode.spec.ts including byte-identical reinstall, merge preservation, Windows path normalisation and Claude-coexistence non-mutation. Frontend: IntegrationsSettings refactored into a generic IntegrationCard rendering the Claude card byte-identically plus the OpenCode card, host client ops, fakeHost fakes, five new component tests, tab hint updated to name coding agents generally. One existing Claude test assertion was scoped from a regex to an exact string because two cards now render Missing lines; behaviour tested is unchanged. Verified myself: mcp 117 passed (Claude 23 unedited), desktop 369, core 185, pnpm build clean.
