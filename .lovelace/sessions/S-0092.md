## Approach

Make clicks anywhere on a Board card or List row toggle selection while checkbox mode is active (anything selected), instead of opening the ticket. Scouted both views myself, then briefed the programmer subagent: extract each view's inline checkbox toggle-plus-shift-range logic into a single toggleSelect helper, branch the card/row click (and List keyboard activation) on selected.size, and add tests in the existing idiom.

## What happened

Board.tsx and List.tsx each gained a toggleSelect(id, shiftKey) helper preserving the existing semantics (shift extends from the anchor through flatIds without moving it; plain toggle moves the anchor). Card and row onClick, and the List row's Enter/Space keydown, now toggle when selected.size > 0 and open otherwise; the checkbox keeps stopPropagation so its click never double-toggles. Seven tests added or updated across board.spec.tsx and views.spec.tsx: body click adds to selection without opening, body click deselects and mode ends when empty (then click opens again), shift-click on the body extends the range, and Enter on a List row toggles in checkbox mode. Two pre-existing tests asserting the old behaviour (a plain body click opens the ticket while a selection exists) were necessarily rewritten to assert the new behaviour; the checkbox-only tests are untouched. The programmer ran a red-first check (reverting the branch made exactly the seven new tests fail). Audited: read all four files' hunks, re-ran pnpm test (132 + 222 + 54 pass) and pnpm build (clean) myself.
