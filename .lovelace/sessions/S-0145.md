## Approach

Add a small copy icon beside the ticket ID in the Properties panel of the ticket detail view, copying the bare ID to the clipboard cross-platform. Scouted the codebase first (ID row in TicketDetail.tsx, icon patterns in icons.tsx, no clipboard plugin installed), then delegated implementation to the programmer agent with a brief covering the Tauri v2 clipboard-manager plugin, control species rules and test requirements.

## What happened

Implemented as briefed and audited. New copyText helper in apps/desktop/src/lib/clipboard.ts routes through the Tauri clipboard-manager plugin when running in the app shell and falls back to navigator.clipboard elsewhere. Copy button added to the ID row (btn btn-secondary btn-icon btn-icon-sm, aria-label "Copy ticket ID") with a 1.5 second tick feedback, timeout cleared on re-click and unmount, and a silent no-tick path when the copy fails. CopyIcon and CheckIcon added to icons.tsx; .btn-icon-sm and .prop-value-id added to app.css using tokens only. Tauri plumbing: plugin dependency in package.json and Cargo.toml, registered in lib.rs, clipboard-manager:allow-write-text permission in capabilities/default.json, regenerated gen/schemas and lockfiles. BulkActions.tsx got a mechanical swap of its direct navigator.clipboard call to copyText. Four new tests in ticketDetail.spec.tsx cover rendering, exact-ID copy, tick appear/revert and the failure path. Verified myself: pnpm test all green (desktop 360/360, core 185, mcp 96), pnpm build clean, cargo check clean.
