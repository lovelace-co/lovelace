## What happened

Merged PR #7 as 83ea351. The local audit found four core failures: three were a stale dist (the concurrency workers import the built package), and the fourth was T-0155, a new test polling the gitignored fixture index.json, which is stale locally and absent on a fresh clone. Fixed and verified both ways, then tagged v0.3.0 at 1213581.

That release run failed on Windows and exposed T-0157, a real defect: Windows refuses a rename onto a file another handle holds open, so writeFileAtomic threw EPERM under any concurrent reader. Every project write in core goes through it, and the desktop app polls index.json while agents mutate, so Windows users would see mutations fail for no visible reason. Worse, the presence stress test had been passing on Windows vacuously: its worker had no error handling, so the first EPERM killed it, the spec's polling loop ended early and the test passed having barely run.

Fixed by retrying the rename on EPERM, EACCES and EBUSY, four immediate attempts then a doubling backoff capped at 20 ms (about 150 ms across sixteen attempts), with the temp file cleaned up when abandoned. The beat worker now tallies errors and the spec asserts every worker completed all its beats, so a dead worker can no longer pass vacuously; the mode-preservation case is skipped on Windows, which models only the read-only bit; and the stress cases take a platform-aware volume and timeout so Windows proves the same assertions without a throughput-driven failure.

Iterated on the ci/windows-atomic-rename branch against the test workflow rather than burning four-platform release builds. Windows and Linux both passed, with the presence case running 3287 ms against the 745 ms of its vacuous pass and no EPERM in the log. Fast-forwarded main to d3a196d, re-tagged v0.3.0, and the run built all four platforms. Verified the draft (14 assets, latest.json at 0.3.0 with all four platforms signed and URLs on the right repo and tag) and published it as the latest release.

The stale ID counter bug bit a third time when filing the release ticket; counters were corrected to T=154 and S=152 before creating T-0155 through T-0157.
