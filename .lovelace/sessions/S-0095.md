## Approach

Read-only review of the hook mechanics behind the concurrent-session conflicts: traced the Claude Code hook wiring in .claude/settings.json through the agent helper (packages/mcp/src/helper.ts) and the core state functions (packages/core/src/mutate.ts) to explain to the owner exactly how the stop guard, active-ticket marker and presence marker interact across sessions.

## What happened

Documented the mechanics: hooks are Claude Code lifecycle events invoking the headless helper, coordinating with the MCP server only through two project-global single-slot files in .lovelace/state/ (active_ticket and presence.json), neither carrying a session identity. Identified four concrete failure modes: (1) the stop-guard clobber, where session A is blocked demanding a record for session B's active ticket; (2) the silent inverse, where the first session to run /done clears the shared marker and the surviving session's guard passes vacuously; (3) presence flicker and mislabelling, since presence.json is one slot overwritten per prompt and cleared by whichever session stops first, including on the blocked-stop path where session-check exits 2 but presence-clear still runs; (4) digest and commit-message misdirection from the shared marker. Key mechanical fact for the fix: Claude Code already delivers session_id on stdin to every hook event and the helper discards it everywhere except guard. This session's own stop was then blocked by the guard demanding a record for T-0095, another session's active ticket: a live reproduction of this ticket. No code was changed.
