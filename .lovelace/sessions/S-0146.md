## Approach

Register a lovelace command on the user's PATH from Settings, General, like VS Code's install command. Settled the ticket's open question first: launcher only, sidecars stay off PATH (they are referenced by absolute path by the integrations). Scouted the Tauri shell and settings UI, briefed the programmer agent, audited the diff and attacked the boundaries myself.

## What happened

New Rust module apps/desktop/src-tauri/src/cli.rs with three Tauri commands: cli_command_status, cli_command_install, cli_command_uninstall. macOS and Linux write a marked launcher script (mode 0755), not a symlink, because the app has no single-instance handling; on macOS the script runs open -b co.lovelace.desktop which activates the running instance. macOS prefers /usr/local/bin when writable and falls back to ~/.local/bin with a note; Linux always uses ~/.local/bin; Windows appends the exe directory to the user-level PATH via PowerShell SetEnvironmentVariable, no elevation and no new crates anywhere. Install repairs stale scripts and removes a stale copy at the other candidate location; a lovelace file without our marker is never overwritten or deleted. Frontend: lib/cli.ts invoke wrappers and a Command line section in GeneralSettings with injectable functions for tests. ADR-0013 records the decision. Audit found one defect in the delegated work: uninstall errored on an unmarked lovelace file and stranded our own script at the other location; fixed to skip files that are not ours. Verified: 9 new Rust unit tests pass via cargo test, desktop tests 364/364 with 4 new component tests, core 185, mcp 96, pnpm build and cargo check clean.
