## Approach

Diagnose why the first signed release crashed on every core host request ("Ran out of executable memory"), fix it, and re-verify the shipped artefact end to end. Evidence first: inspect the installed bundle, reproduce by executing the sidecar directly, and prove the fix by re-signing a copy before touching the pipeline.

## What happened

Root cause: notarisation applies the hardened runtime to every bundled binary, which forbids JIT pages, and the Bun-compiled sidecars need them for JavaScriptCore; the shipped sidecars had the runtime flag and no entitlements. Re-signing the same binary with com.apple.security.cs.allow-jit alone made it answer ping. Fix: src-tauri/entitlements.plist with allow-jit referenced from tauri.conf.json bundle.macOS.entitlements; a local signed build proved Tauri applies the entitlements to sidecars, not just the app binary. Also added a macOS sidecar integrity gate to the release workflow (executes lovelace-host from inside the signed bundle, mirroring the Linux gate) and the T-0141 stapling step. Release run 29816001563 green on all five jobs; verified the downloaded arm64 DMG: sidecar carries allow-jit and answers ping from the mounted image, spctl accepts as Notarized Developer ID, stapler validate passes. T-0141 closed in the same run.
