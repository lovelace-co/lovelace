## Approach

Programmer subagent, audited by the session model. Replaced the conic-gradient ring (which sweeps by angle, so it whips across a card's short edges and crawls along the long ones) with a shared LiveRing SVG component: a rounded-rect stroke normalised by pathLength so an animated stroke-dashoffset moves the comet at constant arc-length speed for any aspect ratio. Two stacked dashes sharing a start position fake the gradient tail (bright head over soft tail) so one animation drives both; direction, 7 second lap and tokens are unchanged, and reduced motion keeps the static 25% ring.

## What happened

Landed as briefed with one defect in the brief itself, caught by the programmer and confirmed in audit: the brief specified the card token (6px) for the ring radius, but .ticket-card actually rounds with the surface token (10px), which the old border-radius inherit had picked up silently. Fixed by pointing the card's ring radius at the surface token with a comment naming the trap. The old conic rules, the orbit angle keyframes and the registered orbit property in tokens.css are removed; the ring markup renders only when a surface is live. Red-first proof on the Board assertion; final state 256/256 desktop tests and a clean vite bundle. The concurrent session's update.spec.tsx type-checked clean this round, so the full desktop tsc also passed.

## Open questions

- The tail is a hard-ended dash with round caps rather than the old gradient fade; at 1.25px it reads clean, but a third middle dash could soften it if the cut ever bothers anyone in motion.
- pathLength on SVG rects needs roughly the same WebKit baseline the old registered-property approach did, so the support floor is unchanged; if an older WebKitGTK ever misrenders the dashes, the fallback is a static full ring, not a broken layout.
