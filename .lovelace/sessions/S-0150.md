## What happened

The investigation found Codex's surface far richer than expected: a full hooks framework (SessionStart, Stop, PreToolUse with exit-2 blocking, PostToolUse, UserPromptSubmit, SessionEnd) taking Claude-shaped stdin payloads, project-level .codex/config.toml with MCP registration for trusted projects, and repo-shareable skills replacing the deprecated user-level custom prompts. ADR-0015 records the mapping: all seven helper behaviours are expressible with no payload adapter (helper.ts untouched); the MCP entry lands as a comment-marker-delimited TOML section in .codex/config.toml (never parsed, no TOML dependency, duplicate-table manual-step guard); hooks in .codex/hooks.json mirroring claude.ts's writeHooks with timeout 3 on SessionEnd; ticket and done become .agents/skills/*/SKILL.md. Named degradations: Codex's trust gates (project trust plus per-hook /hooks trust, stated in the card's install hint), hosted tools bypassing presence-beat, advisory SessionEnd, the root AGENTS.md pointer being a directive with no include mechanism, and the unverified apply_patch tool_input shape behind guard (fails open; permission profiles documented as the hardening option). Backend: assets.ts gained TOML markers, a markers parameter on writeMarkerSection and the extracted hook-command machinery from claude.ts (pure extraction, claude.spec.ts and opencode.spec.ts pass with zero edits); new codex.ts installer and detector; detect_codex and install_codex host ops; 25 tests in codex.spec.ts plus host op wiring tests. Frontend: Codex card through the generic IntegrationCard, host client ops, fakeHost fakes, six component tests. One audit send-back: the programmer had made the Codex props optional with a conditional render to avoid touching existing test prop literals; sent back to make them required like the other two pairs, updating six prop literals without changing any assertion. Verified myself: mcp 144 passed, desktop 375, core 185, pnpm build clean, smoke install output correct on a spaced Windows path. Session-record note: the first log_session attempt this session collided with S-0149 (the local session counter was stale after the branch fast-forward, the same way the ticket counter had been); the original S-0149 was restored from git untouched and this record re-logged under the next free ID.
