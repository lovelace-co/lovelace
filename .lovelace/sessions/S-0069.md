## Approach

Add a corrupt-document repair path: markdown files under the documentation root that fail frontmatter parsing should appear in the Documentation tree with a corrupt badge and offer a Fix Corrupt File button that rewrites them into valid format losslessly. Design settled up front (new host op fix_document, no new MCP tool, corrupt paths derived from snapshot issues in the view); implementation delegated to the programmer subagent, audited, then adversarially gated by a fresh-context verifier.

## What happened

Round 1 implemented the feature end to end: fix_document host op (guards mirroring delete_document, idempotent on valid files, lossless rewrite wrapping the original content under generated frontmatter), HostClient/TauriHost/FakeHost fixDocument, ProjectView wiring, corrupt map and badge plus repair bar in Documents.tsx, .badge-corrupt style, and host plus component tests. The verifier refuted it: a file named null.md repaired to id: null, which YAML coerces so the validator rejects the file while the UI presents it as fixed; non-UTF-8 files were silently mangled; and a symlink write-through was noted. Round 2 fixed the first two (idScalar quoting helper applied to fix_document, create_document and create_folder; fix_document now refuses non-UTF-8 with a clear error); the symlink shape was accepted as the established guard pattern across all document ops. My own re-attack then found digit-leading filenames (007.md) still failed SLUG_RE, so I added a documentSlug helper guaranteeing a letter start (007 becomes doc-007) at all three write sites and strengthened the tests. Verifier re-ran cold and CONFIRMED: 330 tests green, build clean, all fresh probes (true.md, on.md, 1e3.md, emoji-only names, BOM files, CRLF, empty, traversal and prefix-sibling guards) hold, valid files stay byte-identical.
