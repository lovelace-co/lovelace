## Approach

Implement the ADR-0011 versioning foundations: a single version module in core with a derived supported major and a classification helper, typed spec-too-new and spec-needs-migration errors carried through the ConfigError to ProjectError wrap, the host envelope and the desktop store, and a dedicated SpecGate screen for each direction. Scout mapped the error pathway, the programmer implemented to a brief, I audited, and a fresh-context verifier attacked the result.

## What happened

packages/core gained version.ts (SPEC_VERSION as the single source, SUPPORTED_SPEC_MAJOR derived, classifySpecVersion). loadManifest now throws self-contained lowercase messages with code, declared and supported; loadProject preserves them through the ProjectError wrap; the host error envelope carries code, declared, supported, file and line; the desktop store keeps the structure instead of flattening to a string; ProjectView renders the SpecGate screens (update Lovelace for too-new, migration placeholder for too-old) and falls back to the problem note when fields are missing. The MCP server and agent helper surface the classification through the message text; the server still starts on a gated project and reports the error per call. Verifier confirmed end to end over both 4.x and 2.x fixtures with no side effects on gated projects and byte-identical index output for valid ones; its one hardening note (classifySpecVersion silently answering ok for malformed input via NaN) was fixed with a guard that throws on non-semver strings, plus a test. Full suite green (core 140, desktop 224, mcp 56), build green.
