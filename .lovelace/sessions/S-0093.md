## Approach

Make the MCP mutation tools self-describing so agents know how to fill ticket fields: generate the type enum, per-type field guides and value hints from schema.yaml at server start, and add a matching hint per field to describe_schema. Delegated implementation to the programmer against a precise brief, audited the diff, and proved the result live over stdio.

## What happened

Fields were already accepted by create_ticket and update_ticket; the gap was guidance. The tools now advertise: create_ticket's type as a zod enum of the project's defined type names; both tools' fields descriptions carry a generated per-type guide, one line per type with a plain-English value hint per field (enum values resolved via enumValues, reference targets named with a worked id example built from the target type's id_prefix, date format, list shapes, required and default notes); update_ticket's guide ends with the status list. describe_schema returns the same hint per field from one shared renderer. The schema is snapshotted at server start inside try/catch: a broken schema.yaml falls back to the static descriptions and the server still starts, with config errors surfacing per call as before; core stays the single validation authority and the fields parameter deliberately remains permissive. Audit found one phrasing bug (three or more refers_to targets rendered "a task or bug, epic"), fixed to serial "a task, bug or epic". Full suite green (core 132, desktop 222, mcp 54), build green. Live end-to-end over stdio against this repository's own schema confirmed the advertised enum, guides, status list and hints, and wrote T-0103's body through the new body pathway. Sidecars recompiled with the change confirmed present in the binary.
