## Approach

## What happened

The menu already shared the dropdown panel classes; the faintness was a token bug. The menu's only item carries the danger class, and .dropdown-option.danger used --bad-fg and --bad-bg, which are tuned for the app's normal surfaces, while dropdown panels use the inverted pop palette, so the dark theme rendered pale red on a pale panel. Added --pop-bad and --pop-bad-wash to both theme blocks following the existing pop inversion pattern (each theme takes the other theme's danger values) and pointed the danger rule at them. btn-danger on normal surfaces is untouched. Also added the first behaviour tests for ContextMenu: roles, danger flag, select-then-close ordering, Escape, outside and inside pointerdown. 336 tests green, build clean.
