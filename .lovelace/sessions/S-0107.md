## What happened

Implemented and verified. Rust (apps/desktop/src-tauri/src/lib.rs): a StagedUpdate mutex holds the downloaded update; check_for_updates downloads and stages, never installs, with dialogs only on the manual menu path; install_update installs off the main thread and restarts; staged_update lets a new window ask what is already staged; a Check for Updates item sits in the macOS app menu; a 24 hour background loop runs in release builds or when LOVELACE_UPDATE_ENDPOINT is set. My audit added the staged-query round (windows opened after staging, or events beating listener registration, previously lost the affordance) and fixed a strict-mode type error the fix round left in update.spec.tsx (vitest does not typecheck; pnpm build caught it). The verifier confirmed the change overall and refuted three edges, all fixed and re-verified: a malformed LOVELACE_UPDATE_ENDPOINT now refuses to check rather than silently using the production feed (it also used to enable the background loop in debug builds against production), a failed install now withdraws the pill and triggers a background re-stage instead of offering a retry that must fail, and the test now asserts version and notes actually render. Verified: cargo check both profiles clean, full serial suite green (526 tests), pnpm build green, desktop suite 255 green. Manual verification steps for a locally served feed are written into docs/RELEASING.md; the end-to-end run against a signed artifact remains to be performed once (needs the signing key, outside this sandbox).
