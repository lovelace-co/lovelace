# ADR-0001: Bun-compiled sidecar binaries

## Status

Accepted

## Context

The MCP server, agent helper and core host are TypeScript, but the desktop app must work on machines without Node, and Claude Code hooks run in non-interactive shells where a user's version-managed Node is unreliable. The brief requires self-contained sidecars. Candidates: Bun's compiler, Node single executable applications, or shipping a private Node runtime.

## Decision

Compile all three entry points with `bun build --compile` (the `bundle` script in packages/mcp). The compiled binaries pass the same integration suite as the Node builds: the host answers requests, the helper's digest, session-check and guard behave identically, and the MCP server completes the protocol handshake over stdio.

## Consequences

- One binary per tool per platform, roughly 60 MB each; no runtime dependency on the user's machine.
- Hooks and .mcp.json reference absolute paths to app-managed binaries, so PATH and version-manager problems cannot occur.
- Bun's Node compatibility is a build-time risk for new dependencies; the integration tests run against compiled binaries in CI to catch regressions.
- Fallback recorded: if Bun compatibility breaks, ship a private Node runtime under the app's data directory and run the dist JS with it. The host already supports this through LOVELACE_HOST_JS and LOVELACE_NODE.
