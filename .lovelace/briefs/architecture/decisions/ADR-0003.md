# ADR-0003: In-place rich editing atop the block model

## Status

Accepted. Extends ADR-0002.

## Context

The block editor's click-to-reveal-markdown interaction made every edit feel like dropping out of the document into source. The user asked for Notion-style behaviour: formatted text edited directly. ADR-0002's round-trip guarantee (unedited bytes never change) remains non-negotiable.

## Decision

Keep the source-preserving block model exactly as is; replace the editing surface. Blocks render as formatted, directly editable regions (contenteditable). A small inline converter maps the spec's inline subset (bold, italic, code, links) between markdown and DOM in both directions. Enter splits blocks, Backspace on empty removes, markdown prefixes typed at line start autoformat into headings, lists and quotes, task checkboxes toggle in place, and Cmd/Ctrl+B and I apply marks. Tables and out-of-spec raw blocks remain rendered verbatim and are edited in the file.

## Consequences

- Unedited blocks keep byte-identical round trips, by construction, as before.
- An edited block's inline markup may normalise (for example `__bold__` becomes `**bold**`, a hard-wrapped paragraph joins to one line). This is confined to blocks the user changed, which the spec's minimal-diff bar permits.
- Caret management is the new complexity: the editable surfaces are uncontrolled while focused and resynced from the model otherwise.
- Table editing in place is deferred; the cost of a grid editor was not justified yet.
