# ADR-0006: The Air design direction

## Status

Accepted.

## Context

The desktop app read as dated, resembling a stock component kit. Review established the cause was not colour or type but execution habits: a button, an input and a dropdown trigger shared one rectangle recipe, so nothing told the hand what a control does; regions nested filled surfaces (wells holding cards holding chips), draining the tone steps of meaning; and states swapped colours in place with no continuity. Two directions were rejected before this one: adding material (solid signal fills, shadow tiers, edge highlights, cut corners) fought the calm the app is built on, and pure subtraction (controls with no resting surface) destroyed affordance. Several stock treatments were explicitly vetoed during review: left accent bars or rails on hover or active states, selection dots beside options, and underline focus on fields.

## Decision

Modernise by subtraction in regions and chrome, with legible species-specific forms on controls, under the existing laws (no borders, separation by tone and whitespace, the signal never a fill, mono for code only). The rules, recorded in CLAUDE.md's design conventions:

- Every control species has its own form: pressing is a capsule, typing is a 9px well, choosing is a well with a caret, a row in a list, menu or nav is an 8px seat, and tertiary actions are typographic. Affordance is never the thing removed; only page titles are unboxed.
- One surface per region: a region holds one filled layer beside the canvas.
- State moves, never marks: hover brightens or materialises, the active nav seat glides between rows, presses punch 1px down in the stepped easing, selection is colour or the punched hole. Focus is always the full cyan ring. The cyan thread appears only where it already lived: the drop insertion line and the live-work orbit.
- The metre: a seven-step spacing scale, one radius per species, two easings and three durations, all as tokens in tokens.css; no ad hoc values.
- Surfaces bleed, text aligns: seats, wells and capsules extend into the gutter so labels keep the shared left edge.

The full specimen set and a law-by-law compliance sweep live in the modernisation proposal artefact (claude.ai/code/artifact/de14ecda-287c-4702-b274-ddac56036c42). Implementation is epic E-0002, phased P0 to P4 so the app is never half-translated: tokens, then control primitives, then floating surfaces, then views, then choreography.

## Consequences

- Zero amendments to the existing design laws; every colour token and both themes stay byte-identical.
- Priorities render as a dot with tinted text on cards and lists; the pill chip survives only standing alone. Checkboxes become the punched hole, reusing the app's oldest motif.
- The banner strip retires in favour of a corner toast, so messages stop moving the layout.
- CSS and component markup only: core, the file format and round-trip fidelity are untouched.
- The vetoes bind future work: no left rails, no selection dots, no underline focus, no invisible-at-rest controls, no solid signal fills.
