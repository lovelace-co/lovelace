# ADR-0002: Block editor instead of a ProseMirror serialiser

## Status

Accepted

## Context

The document sets byte-identical round-trips as the acceptance bar for the editor and recommended evaluating Milkdown and Tiptap. Both are ProseMirror-based: documents parse into a rich AST and serialise back to Markdown, and the serialiser, not the original file, decides the bytes. List markers, escaping and reflow normalise on every save, which is precisely the churn the bar forbids. Achieving fidelity there means fighting the serialiser indefinitely.

## Decision

Build a block editor. The body splits into blocks (heading, paragraph, list, code, quote, table, blank, raw), each holding its original source text. Blocks render as rich previews; clicking one turns exactly that block into Markdown source for editing. Serialisation concatenates block sources, so an unedited document is byte-identical by construction and an edit touches only the edited block's lines. Constructs outside the supported set are raw blocks: rendered verbatim, not editable.

## Consequences

- The round-trip bar holds structurally; the test suite verifies it across every fixture file and hostile samples.
- Editing within a block is Markdown source rather than fully rich text. This is the Obsidian live-preview model, which the target audience already knows.
- A future rich inline editor can replace the per-block textarea without touching the document model or the fidelity guarantee.
