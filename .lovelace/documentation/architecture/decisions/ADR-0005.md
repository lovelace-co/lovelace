# ADR-0005: Status by outcome through instructions, not hooks

## Status

Accepted.

## Context

Agents need to move a ticket on when work resolves, and the destination depends on the outcome (done, blocked and handed back, or abandoned), which only the agent knows. A declarative hook or on_transition rule cannot choose, because the choice is a judgment, not an observable event; on_transition is reactive and has only run/agent actions, neither of which performs a transition. We also did not want new workflow.yaml data, to keep configuration simple.

## Decision

The agent decides and performs the move itself with update_ticket, which already validates against the workflow's legal transitions. The direction lives in `.lovelace/AGENTS.md`, a Lovelace-owned instruction file the CLAUDE.md section only points to and imports. The guidance is deliberately non-prescriptive: move to a status that reflects the outcome, chosen only from the legal transitions out of the current status; the session-start digest lists those legal next statuses per in-progress ticket so the agent never invents one. The Stop hook enforces that a resolution happened: it blocks when the active ticket is unresolved without a session record, or when the latest record marks the work complete while the ticket was never moved on. The on_transition automations stay as the reactive side-effect layer.

## Consequences

- No new schema and no new MCP tool or action kind; the seven tools and two action kinds stand.
- The move is the agent's judgment, so it is advisory; the legal-transition constraint plus the digest's menu prevent hallucinated statuses, and the Stop hook guarantees a resolution occurred.
- Workflow authors control reachable destinations purely through the transition graph: a status the agent must not reach is simply not a legal move for it.
- The transition graph now has its own home in the Workflow view; Automations is the on_transition rules and the activity they produce.
