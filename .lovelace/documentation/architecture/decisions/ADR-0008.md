# ADR-0008: An index.md convention, informed not enforced

## Status

Accepted

## Context

The documentation tree required fixed, capitalised names: `CONTEXT.md` at the root and an `OVERVIEW.md` in every directory. Filenames were constrained to a slug pattern, and the app locked those names against editing. This was dev-friendly when the project began, but it grew rigid: a developer cannot name their own files, cannot leave a folder without an overview, and meets a validation warning if they do.

The reason those landings were mandatory was navigability, so a fresh agent (or reader) always had a known place to start. The graph view now surfaces documents that are not linked from anywhere as detached nodes, so an orphaned file is visible rather than lost. That removes the need to enforce a landing page for navigability.

## Decision

Move from enforcement to a good default plus a convention.

- A single lowercase **`index.md`** is the documentation entry point. Init scaffolds one in the docs root; nothing else is required. No `CONTEXT.md`, no per-directory `OVERVIEW.md`, no mandatory landings.
- The docs root directory is **`documentation/`** (was `briefs/`), still renamable through the manifest `paths`. The entry doc lives at `documentation/index.md`, so the whole feature is one self-contained subtree.
- **Filenames are unrestricted**: any `.md` name, no slug rule; the only guard is no path separators or `..`, for safety.
- **Inform, do not enforce.** Tools prefer `index.md` and degrade gracefully when it is absent (the digest, `read_document`, and the agent reading-order); the validator stops warning about missing landings; the app drops name-locking and shows a quiet "agents read this first" hint on `index.md`.
- **Retire the "brief" name entirely.** Because nothing has shipped, there is no compatibility to preserve, so the entity is renamed from "brief" to "document" everywhere: the `Document` type and `documents` collection in core, the `read_document`/`create_document`/`rename_document`/`write_document` operations, the `document` link kind and reference target, the `type: document` frontmatter value, the manifest `paths.documentation` key, and the Documentation UI. No "brief" alias or legacy term remains in the code, spec or product docs.

The spec is bumped to **2.0.0**: this removes constructs and changes a default path, so it is a breaking change.

## Consequences

- The documentation tree is the developer's to shape. Full customisation.
- The reading-order guarantee softens to best-effort; the graph covers orphan discovery, which is the trade that makes this safe.
- 2.0 tooling refuses 1.x projects (unknown major). The two projects that exist, the demo fixture and this repository's own `.lovelace/`, are migrated in the same change (rename `briefs/` to `documentation/`, move `CONTEXT.md` to `documentation/index.md`, keep any `OVERVIEW.md` files as ordinary documents, set `spec_version: 2.0.0`).
- The entity is renamed from "brief" to "document" across the whole codebase, spec and product docs (see the decision above); this is a broad but mechanical rename since nothing has shipped.
- Touches core (validation, indexer, digest, `read_document`, init), the MCP `read_document` tool and folder ops, and the Documentation UI.

Tracked in epic E-0004.
