# ADR-0012: Per-session presence with heartbeat liveness

## Status

Accepted. Supersedes [[ADR-0009]].

## Context

ADR-0009's marker file (`state/presence.json`, written at `UserPromptSubmit` and removed at `Stop`/`SessionEnd`) has three failure modes once more than one Claude Code session works a project at once, or a session ends badly.

- **Concurrent sessions fight over one marker.** Two sessions writing the same file at turn start and clearing it at turn end race each other: whichever session stops first clears the marker out from under the session still working, and the ring goes dark while an agent is still active.
- **Focus is read from the singleton active ticket.** The marker's `ticket` came from `state/active_ticket`, the same singleton `state/active/<session-id>` markers (spec 3.1.0) were introduced to stop sessions fighting over. A concurrent session's presence entry pointed at whichever ticket last won the singleton, not its own.
- **The lifecycle is edge-triggered, so it lies during two windows.** A hard-killed session (crash, closed terminal) never fires its end hook, so the marker sits live until the stale cap expires; ADR-0009 set that cap to 120 minutes precisely because the only signal was a start edge and an end edge, with nothing in between to confirm the session was still real. And a session whose `Stop` hook blocks (an unresolved ticket) keeps working past that stop, but nothing refreshed the marker across the block, so a long back-and-forth against one blocked stop looked no more current than the moment it started.

## Decision

Presence becomes one entry per session, kept alive by a heartbeat instead of trusted on a single start timestamp.

- **Entry layout.** `state/presence/<session-id>.json` replaces the singleton, shaped `{ ticket, actor, started_at, beat_at }`. `writePresence`/`clearPresence` take a session ID and validate it against the same pattern `state/active/<session-id>` already uses, so a hostile ID cannot write outside the directory. `readPresences` returns every session's entry, sorted by `started_at` then filename for deterministic output; a pre-3.2 project's singleton `state/presence.json` is read as one more entry and removed on the next presence write, so no manual migration is needed on disk.
- **The beat hook.** `presence-beat` runs on `PostToolUse` with no matcher, so it fires on every tool call. It calls a new `beatPresence`, deliberately kept off `loadProject` (which parses every ticket) since it runs far more often than any other hook: it reads only `manifest.yaml` for paths, re-resolves the session's focus ticket from `state/active/<session-id>` falling back to `state/active_ticket`, and rewrites `beat_at` while preserving `started_at` and `actor`. Garbage collection (entries whose `beat_at ?? started_at` has outlived the cap) runs from `writePresence` instead, once per turn, so the hot path stays a handful of small reads and one write.
- **The session-check fold.** `Stop`'s separate `presence-clear` hook is removed; `session-check` clears the calling session's own entry itself when the stop passes, and leaves it alone when the stop blocks (exit 2). This closes the second lying window directly: a blocked stop no longer needs its marker refreshed by anything else, because the next beat already will, and a passing stop clears presence in the same moment session-check would otherwise report the turn as ending anyway. `SessionEnd` keeps its own `presence-clear` call for the session's active-ticket marker.
- **The cap drops to 15 minutes.** With a heartbeat landing on every tool call, a genuinely dead session's marker goes stale within one interval instead of within the worst case of a single long turn. The manifest key `presence_timeout_minutes` is unchanged in name and meaning; only the default moves, and existing projects that set it explicitly are unaffected.
- **Spec 3.2.0** documents the new file, the heartbeat field, the lifecycle and the lowered default; it is additive over 3.1.0, and pre-3.2 projects remain valid without a migration step.

## Consequences

- Multiple sessions working the same project each show their own ring, correctly, instead of one session's stop erasing another's marker.
- The heartbeat spawns the agent helper once per tool call. That is the accepted cost of closing the blocked-stop lying window without inventing a longer-lived process; the helper is already a short-lived Node/Bun sidecar spawned for other hooks on the same cadence.
- The false-positive window (a dead session shown live) shrinks from up to 120 minutes to up to 15, since liveness now depends on a heartbeat that stops the moment the session actually does.
- No new MCP tools; the eight-tool constraint stands. The markers remain machine-local under `state/`, already gitignored.
