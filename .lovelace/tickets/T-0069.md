## Description

The live-ticket thread dies mid-session because presence is inferred from .lovelace file activity with an exponential decay (about 65 seconds of life per write), while a working agent barely touches .lovelace. Replace inference with the real signal.

- The agent helper gains turn-boundary hook handlers: UserPromptSubmit writes .lovelace/state/presence.json (actor, ticket, startedAt; machine-local, gitignored); Stop and SessionEnd delete it. install_claude registers the new hooks.
- The app derives liveness directly: thread on the card iff the presence file names that ticket and is younger than the stale cap; seat dot awake iff present; elapsed is now minus startedAt. The energy, half-life, decay and threshold machinery is deleted; only the user interface survives.
- The changed-ticket glow becomes a plain fixed 60 second window per changed ticket.
- The stale cap defaults to 2 hours and is configurable per project in Settings (General), persisted in the project settings, for long-running projects.

## Acceptance criteria

- [ ] The thread runs for the whole time an agent is processing and rests between turns, regardless of how rarely .lovelace changes.
- [ ] A killed session stops showing live after the stale cap; the cap is editable in Settings and persists per project.
- [ ] presence.ts contains no decay arithmetic; the visuals are unchanged.
- [ ] pnpm test and pnpm build pass, including new helper and presence specs.
