## Description

The first signed and notarised release (v0.1.0, run 29810434632) launches but every core host request fails with "core host produced no output: Ran out of executable memory while allocating 128 bytes."

Cause: notarisation requires the hardened runtime, and the pipeline now signs every bundled binary with it. The sidecars are Bun-compiled and JavaScriptCore needs JIT executable pages, which the hardened runtime forbids unless the binary carries the com.apple.security.cs.allow-jit entitlement. The shipped sidecars have the runtime flag and no entitlements, so JavaScriptCore aborts on its first executable allocation. Unsigned builds never hit this, which is why every earlier build worked.

Verified on the installed app: codesign shows flags=0x10000(runtime) with no entitlements and the ping op reproduces the crash; re-signing the same binary with allow-jit alone makes ping succeed.

## Acceptance criteria

- [ ] Sidecars in the signed bundle carry com.apple.security.cs.allow-jit (verify with codesign -d --entitlements - on the DMG contents).
- [ ] The ping op succeeds when the sidecar from a signed bundle is executed directly.
- [ ] spctl still accepts the app and notarisation still passes.
