The release pipeline signs and notarises the macOS app (Apple returns Accepted) but never runs stapler, so the ticket is not attached to the bundle: xcrun stapler validate fails with error 68 while spctl accepts the app via an online lookup. A first launch on a machine without network access cannot verify notarisation and falls back to the unidentified-developer flow.

Fix: in the release workflow, after the Tauri build and before hdiutil assembles the DMG, run xcrun stapler staple on the built Lovelace.app when HAS_APPLE_SIGNING is true. Note the updater .app.tar.gz is generated during bundling, before any stapling can happen; that archive stays unstapled, which is acceptable because updater installs replace an app that is already running online.

Acceptance criteria:
- xcrun stapler validate passes on the app inside the DMG from a release run.
- spctl assessment still accepts the app.
- The updater signature (minisign) still verifies against the published .sig.
