## What happens

In the block editor (ticket body, comment composer, document editor), clicking the link button (the infinity glyph) in the toolbar does nothing. No dialog appears and the selection is unchanged.

## Cause

The button calls `window.prompt('Link URL')` and dispatches `TOGGLE_LINK_COMMAND` with the result (`apps/desktop/src/editor/BlockEditor.tsx`, Toolbar). Two problems compound:

- Tauri's system webview (WKWebView on macOS) does not reliably implement native JS dialogs, so `window.prompt` can return without ever showing anything. The click then looks dead.
- With a collapsed caret (no text selected) the toggle command has nothing to wrap, so even a successful prompt is a silent no-op.

## Fix

Replace `window.prompt` with a small in-app URL popover on the editor's raised surface, consistent with the reference picker pattern and the control species rules (typing happens in a well, no native browser chrome). It should:

- Open anchored to the toolbar button, focus its URL input immediately, confirm on Enter, dismiss on Escape.
- Apply `TOGGLE_LINK_COMMAND` with the entered URL to the selection captured when the popover opened (the selection must survive the focus move into the input, as `insertReference` already handles for pickers).
- With a collapsed selection, insert the URL as its own link text rather than doing nothing.
- Offer toggle-off when the selection is already a link.

## Acceptance

- Selecting text and clicking the link button opens the popover; entering a URL turns the selection into a link that saves as `[text](url)` markdown.
- Clicking with no selection still produces a visible result (a link whose text is the URL).
- No use of `window.prompt`, `window.alert` or `window.confirm` remains in the editor.
- A rendering test covers the popover opening and the command dispatch; `pnpm test` and `pnpm build` pass.
