## What happens

On the ticket detail view, clicking Edit under the body swaps the rendered markdown for the block editor, but the editor does not take keyboard focus. The Edit button that held focus has just unmounted, so focus falls back to the document body and keystrokes go nowhere. The user experience is: click Edit, type, nothing happens. The same applies to the comment composer on ticket detail and the document editor on the Documents view, both of which mount the editor on intent without focusing it.

## Cause

`BlockEditor` never focuses the Lexical editor when it mounts. Nothing else is at fault: the editor mounts with `editable: true`, no global key handler swallows plain keys, and no CSS blocks the region.

## Fix

Focus the editor on mount when it is not read-only (Lexical's `AutoFocusPlugin` from `@lexical/react`). All three mounts are edit-on-intent, so focusing on mount is always what the user asked for, and it honours ADR-0010: the editor materialising on click should be immediately typeable.

## Acceptance

- Clicking Edit on a ticket body places the caret in the editor; typing works immediately.
- Same for Add a comment and for document editing.
- A rendering test asserts the mounted editor's contenteditable takes focus.
- `pnpm test` and `pnpm build` pass.
