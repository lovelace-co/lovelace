## Context

The live-work orbit on the board is driven by `state/presence.json`, a singleton written by the Claude Code hooks: `UserPromptSubmit` writes it, `Stop` and `SessionEnd` delete it (ADR-0009). Three structural problems follow:

1. With two concurrent sessions, one session finishing deletes the marker while the other is mid-turn, and each new prompt overwrites `started_at`, so the ring flickers and the elapsed timer resets. This is the same one-session assumption [[T-0099]] fixes for session-check.
2. The marker's `ticket` comes from the singleton `state/active_ticket`, not the calling session's own marker in `state/active/<session-id>`, so the ring can sit on the wrong ticket.
3. The marker is edge-triggered. A killed session leaves it lying (false ring for up to the 120 minute cap), a turn longer than the cap goes dark mid-work, and when session-check blocks a Stop, the parallel presence-clear hook has already deleted the marker so the forced continuation (logging the session, moving the ticket) always runs ring-off.

## Decision

Presence becomes one file per session under `state/presence/<session-id>.json`, carrying `ticket`, `actor`, `started_at` and a new `beat_at`. Liveness is heartbeat-based: a PostToolUse hook refreshes `beat_at` on every tool call, so the stale cap can drop from 120 to 15 minutes. The Stop-time clear folds into session-check: it clears this session's entry only when it allows the stop. SessionEnd clears the session's entry as today. The app unions fresh entries and can show several rings at once, one per genuinely worked ticket.

## Acceptance criteria

- `packages/core` reads and writes per-session presence entries with the same session-id filename guard as the active markers, skips torn files, returns entries deterministically sorted, garbage-collects entries older than the cap, and still reads a legacy `state/presence.json` as one entry while cleaning it up on write.
- The helper gains `presence-beat` (PostToolUse, all tools) that refreshes `beat_at` and re-resolves the session's focus ticket without loading the whole project on the hot path; `presence-start` stamps the calling session's ticket (per-session marker first, singleton fallback); `session-check` clears presence only on a passing stop; `presence-clear` remains for SessionEnd.
- `install_claude` wires the new PostToolUse hook and removes a stale Stop presence-clear entry from existing installs; this repository's own `.claude/settings.json` is migrated the same way.
- The snapshot carries all fresh entries; Board and List light every focused ticket with its own elapsed time (earliest start wins when two sessions share a ticket).
- The Rust watcher and core's `watch.ts` react to the presence directory.
- SPEC.md bumps to 3.2.0 documenting the new state files and the 15 minute default; an ADR records the decision as the successor to ADR-0009.
- `pnpm test` and `pnpm build` pass, with tests updated across core, mcp and the app.

## Non-goals

Writing presence from the MCP server for non-hook clients (tracked separately), and view parity beyond Board and List (tracked separately).
