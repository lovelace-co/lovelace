## Description

The MCP tools accepted field values through the fields object, but nothing taught an agent what to send: fields was advertised as an opaque object, type as a bare string, and describe_schema listed definitions without saying what a legal value looks like. In line with the principle that forms are generated from the schema at runtime, the tool surface now teaches itself:

- create_ticket advertises type as an enum of the project's defined type names.
- create_ticket and update_ticket carry a generated per-type field guide in their fields descriptions, one line per type with a plain-English value hint per field (enum values resolved, reference targets named with a worked id example from the target's id_prefix, date format, list shapes). update_ticket's guide ends with the status list.
- describe_schema returns a hint per field using the same renderer, so an agent sees identical wording everywhere.
- The guidance is a snapshot from server start with a safe fallback: a broken schema.yaml leaves the static generic descriptions and the server still starts, with config errors surfacing per call as before. Core remains the single validation authority; the tool layer deliberately stays permissive.

## Acceptance criteria

- [x] create_ticket advertises the type enum generated from schema.yaml.
- [x] Both tools' fields descriptions carry the per-type guide with value hints; update_ticket lists the statuses.
- [x] describe_schema fields each carry a hint, with enum values and reference id examples.
- [x] A corrupted schema.yaml still yields a starting server with the static descriptions and per-call errors.
- [x] pnpm test and pnpm build green.
