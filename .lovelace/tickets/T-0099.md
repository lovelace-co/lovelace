## Description

The session-record stop hook and the active-ticket marker assume a single session. The marker is one slot per project, so with two concurrent Claude Code sessions the second set_active_ticket overwrites the first, and each session's stop guard then demands a session record for whichever ticket is currently marked, including one the stopping session never worked. The blocked session cannot satisfy the guard without logging a session against the other session's ticket.

Concurrent sessions are now the normal working mode in this repository, so the marker and the guard need to be session-scoped rather than project-scoped, or the guard needs to check only records for tickets the stopping session actually touched.

## Acceptance criteria

- [ ] Two concurrent sessions with different active tickets can each stop cleanly after logging their own session record.
- [ ] A session that worked no ticket is not blocked by another session's active ticket.
- [ ] The digest and commit-message injection still resolve the right ticket for each session.
