## Description

Release builds currently check the feed on launch and call download_and_install silently (apps/desktop/src-tauri/src/lib.rs, the updater block in setup). Replace that with a flow the user can see and control:

- Check and download only, never install unprompted. When a download completes, emit an event to the frontend carrying the new version and its notes.
- The frontend shows a quiet affordance that an update is ready. It must pass the attention test: it announces without demanding, no modal, no badge pulsing for attention. Clicking it invokes a command that installs the update and restarts the app. On Windows install() hands over to the installer which relaunches; the same single action covers all three platforms.
- Add Check for Updates to the app menu. It runs the same check, shows the affordance when something is found, and reports plainly when the app is up to date.
- Re-check on a 24 hour interval while the app runs. Lovelace stays open for weeks; a launch-only check means updates never land.
- Support an endpoint override through an environment variable (LOVELACE_UPDATE_ENDPOINT) so a staging feed can be exercised end to end. Signature verification against the committed pubkey still applies to any endpoint, so the override is safe.

Design constraints (settled decisions, do not reinvent): control species per ADR-0006 (a pressable affordance is a capsule), Geist Sans for everything the user reads, no ad-hoc spacing or colours, state moves rather than marks. Australian English and no em dashes in every user-facing string.

## Non-goals

- No release-notes viewer beyond showing the notes text in or near the affordance.
- No settings toggle for update behaviour; there is one behaviour.
- No change to the feed format or the endpoint in tauri.conf.json.

## Acceptance criteria

- [ ] With an update available, a release build downloads it in the background and shows the affordance; nothing installs until the user acts.
- [ ] Activating the affordance installs and restarts into the new version on macOS; the Windows and Linux paths compile and follow the plugin's documented behaviour.
- [ ] Check for Updates appears in the app menu and reports both outcomes (update ready, up to date).
- [ ] A running app re-checks after the interval without a relaunch.
- [ ] A component test drives the affordance from a mocked update-ready event.
- [ ] Manual verification against a locally served feed (signed artifact plus latest.json, endpoint override) is performed once and the steps recorded in docs/RELEASING.md.
- [ ] pnpm test and pnpm build pass.
