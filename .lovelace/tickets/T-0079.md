## Description

Two pre-existing schema editor issues carried over from the old workflow editor, found by the Phase 3 verification of E-0005:

1. `apps/desktop/src/lib/schemaRows.ts` emits a field `default` only in the enum branch, while core accepts and applies defaults on any field type. A hand-authored non-enum default (for example `default: 3` on a number field) makes the Settings draft read as dirty on open, and Save silently drops the default. The same normalisation class applies to an explicit `label` equal to Title Case(name) and an explicit `required: false`.

2. `apps/desktop/src/components/FieldsEditor.tsx` hides any row whose machine name is `title` (to pin the locked row), so renaming another field to `title` makes its row vanish from the editor. Core rejects the duplicate on save, but the row should stay visible; hide only the pinned locked row itself.

## Acceptance criteria

- [ ] Non-enum defaults round-trip through the schema editor without dirtying or being dropped.
- [ ] Explicit label and required values survive a save byte-faithfully (round-trip fidelity).
- [ ] A field renamed to a colliding machine name stays visible in the editor and surfaces the core validation error on save.
