## Description

Caught by the first CI release run (macOS job, run 29187958890): the host op test "init scaffolds a project from a custom schema" failed with ProjectError "project_id: Expected string, received number" from loadProject via the snapshot op.

Corrected root cause (the original narrative below was partly wrong): project_id is not folder-derived; it is randomBytes(6).toString('hex'), which by chance can be entirely digits (roughly one init in a few hundred), and that is what CI drew. The deterministic, user-triggerable vector is the manifest name field: the app prefills the project name from the target folder's basename (Welcome passes it into InitWizard), so a folder named "2048" (or a name of "true", "null", "1e3") was spliced unquoted into manifest.yaml, read back as a non-string, and the project could never load again. The user name written into actors.yaml had the same flaw. All three are the same bug class: initProject hand-assembles YAML from template strings without quoting ambiguous scalars, violating the principle that the app must never produce a file the validator rejects.

## Fix

packages/core/src/init.ts gains a yamlScalar helper built on the yaml package's stringify, which quotes a scalar only when its plain form would round-trip as something other than the same string. project_id, name and the actor name route through it. Unambiguous values keep exactly their previous bytes (verified by diff); quoting also incidentally fixes names containing ": " or "#", which would previously have produced invalid YAML. The validator is untouched: hand-edited unquoted numeric ids still fail with the existing clear message.

Regression test: packages/mcp/test/host.spec.ts inits into a folder literally named 2048 and asserts the snapshot loads with name "2048" as a string.

## Acceptance criteria

- [x] init into a directory named entirely of digits produces a project that loads and validates cleanly; a regression test covers it.
- [x] Every free-string scalar initProject writes is quoted when ambiguous; boundary values (007, 1e3, null, true, 0x1A, empty, ": ", "#") verified to round-trip.
- [x] Hand-edited unquoted numeric project_id still fails validation with the existing clear message.
- [ ] pnpm test and pnpm build pass (full serial suite re-run pending alongside the T-0125 fixes; scoped suites green).

## Notes
