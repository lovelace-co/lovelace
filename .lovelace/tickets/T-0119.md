## Context

The Rust watcher emits one debounced `lovelace://changed` event per batch, and the store treats every event as an external change: it reloads the snapshot and shows the "Files changed on disk; the view has been refreshed" toast (`ProjectView.tsx:317`). Presence markers are the one piece of `state/` the watcher deliberately reacts to, so every agent turn boundary (and, after T-0118, every heartbeat) pops the toast even though nothing the user reads has changed.

## Decision

The watcher classifies each batch: when every non-ignored path in the batch is a presence marker, the emitted event carries `presenceOnly: true`. The store still reloads the snapshot (the ring must move) but only raises the external-change toast when the batch touched real content.

## Acceptance criteria

- `lib.rs` sends the presence classification through the debounce channel and emits it in the event payload; a mixed batch (presence plus a ticket edit) counts as a real change.
- The app's `HostClient.watch` callback receives the flag; `store.tsx` reloads on every event but sets `externalChange` only for real changes.
- The fake host used by app tests reflects the new callback shape.
- `pnpm test`, `pnpm build` and `cargo check` in `apps/desktop/src-tauri` pass.

## Non-goals

Changing what the watcher watches, and any change to the toast component itself.
