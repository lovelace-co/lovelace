## Description

Clearing a ticket description in the app produces a file shape core would never write. The host's write_ticket_body op reassembles the file as the frontmatter block plus a leading newline prepended to the body, so an empty body yields a dangling blank line after the closing fence. Core's canonical body-less shape (createTicket and updateTicket since T-0098) ends at the fence with no trailing blank line. The two writers disagree, so clearing a description through the app then saving the same ticket through core produces a spurious one-line diff, against the round-trip and minimal-diff principles.

The natural fix is the follow-up noted on T-0098: route write_ticket_body through core updateTicket's body pathway instead of splicing the file in the host, which also honours the principle that all app mutations route through core validation.

## Acceptance criteria

- [ ] Clearing a description in the app leaves the file in core's canonical body-less shape, ending at the closing fence.
- [ ] A non-empty body written through the app is byte-identical to the same body written through core.
- [ ] write_ticket_body no longer hand-splices the file; it routes through core.
- [ ] Round-trip tests cover app-written then core-saved files.
