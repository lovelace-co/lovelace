## Description

With three integrations (Claude Code, OpenCode, Codex) the Integrations tab in Settings stacks three full cards, each showing a description paragraph, a status line, a git hook checkbox and an install button at rest. That is too many controls at rest (the ADR-0010 diagnostic) and reads as clutter.

Rework `apps/desktop/src/components/IntegrationsSettings.tsx` to the settled read-first pattern:

- At rest the tab shows one row per integration (species: seat, `--radius-seat`, quiet resting surface, bleeding into the gutter so labels keep the shared left edge). Each row carries the product name in sans and a plain-English state on the right: the existing `installed` badge when fully installed, otherwise subtle text "Partially installed" or "Not installed". No description, no checkbox, no button at rest.
- Clicking a row opens that integration's panel on the region's raised surface (`--raise`), one open at a time; clicking the open row closes it. The panel holds what the card holds today: the description, the status summary with its Missing line, the git hook checkbox, the install/reinstall button, and the written/manual results after an install. Copy is unchanged.
- Statuses still load on mount for all three rows, since the rows must read correctly at rest.
- Conventions: tonal surfaces with no borders; state moves, never marks (the open row's surface materialises, no accent bars, focus is the full cyan ring); spacing and radii on the metre (`--sp-*`, species tokens) with no ad-hoc values; the row is a real button with `aria-expanded`.

## Tests

Update the integration card tests in `apps/desktop/test/views.spec.tsx` to open a row before asserting on panel content; assertions on copy, install behaviour, badge, and written/manual rendering stay equivalent. Add coverage that only one panel is open at a time and that rows show the right at-rest state for each status shape.

## Acceptance criteria

- At rest the Integrations tab renders three rows and zero install controls.
- One panel at a time; toggling works; `aria-expanded` reflects state.
- All existing behaviours (install with git hook flag, busy label, result rendering, status refresh after install) work inside the panel, with copy unchanged.
- `pnpm test` and `pnpm build` pass.

## Non-goals

- No behaviour changes to install/detect logic in packages/mcp.
- No redesign of other Settings tabs.
