## Description

The first CI release run (Windows job, run 29187958890) ran the test suite on Windows for the first time anywhere: 85 of 190 packages/core tests failed, spread across validate, mutate, schema, misc, index-gen, schema-config, order, config, settings and migrations specs. pnpm -r aborted at core, so @lovelace/desktop and @lovelace/mcp have not yet been exercised on Windows at all.

Observed failure patterns from the logs: unknown-key passthrough lost on the manifest and on nested type/status/field entries while the schema top level survives; the digest missing in-progress tickets from the demo fixture. The shape suggests path handling (forward-slash assumptions against Windows backslash paths) and possibly line endings (the repo has no .gitattributes, and Windows runners check out with autocrlf, which also threatens the byte-identical round-trip guarantees).

Windows is a target platform (BRIEF: macOS, Linux, Windows), so this blocks any real release: the release workflow deliberately gates all four platform builds on a green suite.

Verification constraint: no Windows machine is available locally. Fixing needs a cheap iteration loop first: a tests-only workflow (Windows and Linux runners) triggered manually or on a ci/ branch, so portability fixes are verified without paying for full release builds.

## Acceptance criteria

- [ ] A tests-only GitHub Actions workflow runs the serial suite on windows-latest and ubuntu, triggered by workflow_dispatch and pushes to ci/** branches.
- [ ] The full suite (core, desktop, mcp) passes on Windows and Linux in that workflow.
- [ ] Root causes are recorded (path separators, line endings, whatever else surfaces), and fixes live in the product code, not in test-only shims, wherever the product itself is wrong on Windows.
- [ ] A .gitattributes pins text files to LF if line endings turn out to matter, protecting round-trip fidelity on Windows checkouts.
- [ ] pnpm test and pnpm build pass on macOS as before.
