## Description

SPEC.md section 4 promises minor and patch tolerance with warnings for unknown constructs, but parsing silently strips unknown keys (plain zod objects) and writeSchema rebuilds types, statuses and priorities wholesale from the stripped parse, destroying anything newer-minor tooling or a hand edit wrote. This is both the minor-version safety gap and a live round-trip bug for hand-authored files, adjacent to [[T-0079]]. [[ADR-0011]] records the decided model.

- Config parsing passes unknown keys through; validation reports each as a warning (schema/unknown-key, naming file and key), never an error.
- writeSchema patches the keys it knows per node and leaves unrecognised keys in place, as writeManifest already does.
- The declared spec_version is a floor: tooling never bumps it opportunistically; only a migration rewrites it.

## Acceptance criteria

- [ ] A schema.yaml carrying an unrecognised key loads with a warning naming the file and key.
- [ ] A schema-editor save preserves unrecognised keys byte-for-byte outside the edited nodes.
- [ ] Round-trip fidelity and index determinism suites stay green.
- [ ] Tests use fixtures with unknown keys at manifest, type, status and field level.
