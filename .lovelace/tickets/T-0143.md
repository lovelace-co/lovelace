## Problem

On a fresh Windows install, every Lovelace Claude Code hook fails as soon as a session starts. Claude Code reports, for each hook event:

```
UserPromptSubmit hook error
Failed with non-blocking status code: /usr/bin/bash: line 1:
C:UsersFredyLievanoAppDataLocalLovelacelovelace-agent.exe: command not found
```

The same failure fires for the Stop hook (and by extension SessionStart, PreToolUse, PostToolUse and SessionEnd, since they all share the helper path). The MCP server itself works: `.mcp.json` sessions connect fine, so the breakage is confined to the hooks.

## Root cause

1. `siblingCommands()` in `packages/mcp/src/host.ts:67` derives the helper and MCP paths from `process.execPath`. On Windows that is a native backslash path, for example `C:\Users\FredyLievano\AppData\Local\Lovelace\lovelace-agent.exe`.
2. `writeHooks()` in `packages/mcp/src/claude.ts:154` writes that string verbatim into `.claude/settings.json` hook commands, for example `C:\Users\...\lovelace-agent.exe digest`.
3. Claude Code executes hook commands through bash (`/usr/bin/bash`, Git Bash on Windows). In bash an unquoted backslash is an escape character, so `C:\Users\FredyLievano\...` collapses to `C:UsersFredyLievano...` and bash reports "command not found".

`.mcp.json` is unaffected because Claude Code spawns MCP server commands directly rather than through a shell, so backslashes survive there.

## Possible solution

In `writeHooks()` (or centrally in `siblingCommands()` plus the `installClaudeAssets` entry point, so caller-supplied overrides are normalised too):

1. Normalise the helper and MCP paths to forward slashes before writing any config: `path.replace(/\\/g, '/')`. Forward slashes are accepted by bash, by Claude Code, and by the Windows file APIs, so this is safe on every platform.
2. Quote the helper path in each hook command, for example `"C:/Users/.../lovelace-agent.exe" digest`, so paths containing spaces (common under `C:\Users\First Last\...`) also survive bash word splitting.

Two follow-on considerations for the same change:

- Migration: `ensure()` in `packages/mcp/src/claude.ts:169` dedupes by exact command string, so re-running install on an already broken Windows project would add the corrected entries alongside the stale backslash ones. The install should strip existing Lovelace hook entries whose command matches a known helper suffix before inserting the corrected form, following the ADR-0012 stale Stop entry pattern at `packages/mcp/src/claude.ts:187`.
- `writeMcpJson()` at `packages/mcp/src/claude.ts:132` splits `mcpCommand` on spaces to separate command from args, which mangles any absolute path containing a space regardless of slash direction. Quoting or a smarter split should land with this fix, or be filed separately if it grows.

## Acceptance criteria

- On Windows, a fresh `install_claude` writes hook commands with forward-slash, quoted paths, and every hook (SessionStart, UserPromptSubmit, Stop, PreToolUse, PostToolUse, SessionEnd) executes without "command not found".
- Re-running install over a project with the old backslash entries replaces them rather than duplicating them, and leaves user-authored hooks untouched.
- `.mcp.json` continues to work on all platforms after normalisation.
- Unit tests in `packages/mcp/test/claude.spec.ts` cover a Windows-style `helperCommand` (backslashes and a space in the path) asserting the written hook command form, plus the migration of a stale backslash entry.
- macOS and Linux installs are byte-identical to today's output where paths contain no backslashes or spaces.
