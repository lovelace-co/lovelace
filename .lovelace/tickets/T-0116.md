## Description

Publishing is currently by hand on one machine, and a hand-assembled latest.json can silently break updates for every install. Build a GitHub Actions workflow, triggered by pushing a v* tag, that produces the whole release mechanically:

- A build job per platform: macOS aarch64, macOS x86_64, Windows x86_64, Linux x86_64. Each installs Node 22, pnpm, Bun and the Rust toolchain, then runs pnpm install, pnpm build, pnpm test, prepare-sidecars.sh and tauri build. Sidecars are compiled fresh inside the job so a release can never ship stale sidecars.
- Updater signing uses TAURI_SIGNING_PRIVATE_KEY from repository secrets. OS code signing (Apple certificate and notarisation, Windows certificate) engages when its secrets are present and degrades to unsigned installers with a visible warning in the job summary when they are not; absence is not a failure while certificates are still being procured.
- macOS DMGs use the headless workaround already documented in docs/RELEASING.md (build with --bundles app, assemble the DMG with hdiutil).
- A final job assembles latest.json mechanically: version read from tauri.conf.json, each platform's .sig contents inlined, and url fields built from a single base-URL workflow variable. The binaries' public home is decided on T-0117 (GitHub Release assets by default); changing it must change one line here, not the workflow's shape.
- Everything (installers, update packages, .sig files, latest.json) is published to a draft GitHub Release as the artifact store. The feed itself ships through the website repository; that promotion path is owned by T-0117.

## Non-goals

- No deployment to lovelace.co or the website repository from CI.
- No channels, rollout logic or scheduling.
- No change to app code.

## Acceptance criteria

- [ ] Pushing a test tag produces a draft GitHub Release holding installers, update packages, signatures and a latest.json whose signatures verify against the pubkey committed in tauri.conf.json.
- [ ] The version in the built latest.json matches tauri.conf.json and the tag.
- [ ] The url fields in latest.json derive from one base-URL variable in the workflow.
- [ ] Missing OS signing secrets produce unsigned installers and a warning in the job summary, not a failed run.
- [ ] The workflow runs pnpm test and pnpm build on every platform before bundling.
- [ ] docs/RELEASING.md points at the workflow for the build steps it now owns.
