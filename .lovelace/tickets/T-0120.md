## Context

The live-work signal renders fully on the Board (orbit ring, raised card, cyan ID with elapsed time). The List view applies a `live` class to the row but no `.list-row.live` rule exists in the stylesheet, so only the ID chip changes. The ticket detail page shows nothing: you can be looking at the exact ticket an agent is working and see no signal.

## Decision

One live treatment, three surfaces. The orbit ring rule generalises so the list row carries the same masked conic ring at its own radius, and the ticket detail header shows the cyan ID treatment with elapsed time, matching the meta rows. The reduced-motion fallback (static cyan ring) covers every surface that carries the ring.

## Acceptance criteria

- A live list row shows the orbit ring at the seat radius, sharing the keyframes and gradient with the card rule rather than duplicating them.
- The ticket detail header shows the live cyan ID and elapsed time when the open ticket is being worked, using the shared presence derivation.
- `prefers-reduced-motion` shows the static ring wherever the animated ring would appear.
- No new colours, spacing or timing values: only existing tokens.
- `pnpm test` and `pnpm build` pass.

## Non-goals

A live signal on the Graph view, and any change to what counts as live (that is T-0118).
