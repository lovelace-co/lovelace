## Description

Consolidate everything the user configures into one Settings destination, and re-scope the sidebar so "Activity" means only read-only history. See ADR-0006 for the decision and rationale.

Target sidebar: Work (Board, List) / Knowledge (Documentation, Graph) / Activity (Sessions, Runs) / Settings at the bottom with a gear.

Settings tabs mirror onboarding: General, Statuses, Types & fields, Automations, Team, Integrations. Tabs exist only in Settings; every other destination is a single flat view.

Delivered across five phases (the child tickets), landable incrementally: nothing visible changes until Phase 4.

## Acceptance criteria

- [ ] One Settings destination hosts all configuration, with a single level of tabs.
- [ ] Sessions and automation Runs sit under Activity; nothing configurable remains there.
- [ ] Every onboarding-collected setting (name, identity, statuses, types, fields, priorities, Claude integration, git hook) is editable in Settings.
- [ ] pnpm build and pnpm test pass.
