## Description

Agents working in Lovelace projects sometimes write project documentation into a `docs/` folder at the repository root (or elsewhere in the application tree) instead of `.lovelace/documentation/`. Those files never validate, never index, and fall outside the project's documentation. The generated `.lovelace/AGENTS.md` mentions the documentation folder only in passing; nothing tells an agent where new documents must go, or that a repo-level docs folder is the wrong place.

## Scope

- `packages/mcp/src/claude.ts` (`agentsMdSection()`): add clear direction that all project documentation is written under `.lovelace/documentation/` and tickets live only in `.lovelace/tickets/` via the MCP tools; a repo-level `docs/` or similar folder is never the destination for project documentation.
- Regenerate this repository's own `.lovelace/AGENTS.md` so it carries the new section.
- Root `CLAUDE.md`: the Lovelace block is a generated pointer by design; keep it that way, but ensure the repository's own guidance also states the rule.

## Acceptance criteria

- `agentsMdSection()` names `.lovelace/documentation/` as the only home for project documentation and `.lovelace/tickets/` (via MCP tools) as the only home for tickets, and says a repository docs folder is not a substitute.
- This repo's `.lovelace/AGENTS.md` matches the regenerated template.
- `pnpm test` and `pnpm build` pass.

## Non-goals

- No validation or tooling change that scans for stray docs folders; this is instruction content only.
- No change to the CLAUDE.md pointer design.
