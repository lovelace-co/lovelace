## Context

Presence is written only by the Claude Code hooks, so any other MCP client working this project (or an install where the hooks failed to merge) shows a permanently still board no matter how much agent work happens. ADR-0009 accepted this false-negative deliberately; T-0118's heartbeat model reopens the option cheaply.

## Proposal

The MCP server refreshes a per-connection presence entry as a side effect of every tool call. No new tool, so the eight-tool constraint stands. The server cannot see turn boundaries, so its entries are pure heartbeat with the stale cap as the only off switch; the entry uses the server's connection identity in place of a Claude Code session ID.

## Open questions

- Whether a tool-call heartbeat alone reads as "working" honestly enough, given the ring would decay on the cap rather than rest at turn end.
- Whether hook-written and server-written entries for the same session double-count, and how to dedupe them.
