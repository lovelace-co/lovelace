## Description

`packages/core/test/concurrency.spec.ts`, the case "index.json stays parseable and never drops a fixture ticket while two workers race", polls `.lovelace/index/index.json` in the copied fixture from the moment the race starts. That file is derived and gitignored (`examples/demo-project/.gitignore`), so `tempFixture` copies whatever happens to be on disk:

- Fresh clone or CI: the file does not exist, so every read before the workers regenerate it throws, and `expect(tally.tornIndex).toBe(0)` fails.
- Local machine with a stale copy: the file predates `T-0005`, so every early read reports that ticket missing and `expect(tally.missing).toEqual({})` fails. Observed as `expected { 'T-0005': 3164 } to deeply equal {}`.

Neither failure says anything about concurrency correctness; the assertions are about what the race does to a valid index, so the test has to establish one first.

## Fix

Call `writeIndex(project)` on the freshly copied fixture before spawning the workers.

## Acceptance criteria

- The spec passes with a stale fixture `index.json` present and with the file deleted (the fresh-clone case).
- `pnpm test` and `pnpm build` pass.
