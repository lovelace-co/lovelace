## Description

macOS users expect to install desktop tools with Homebrew (`brew install --cask lovelace`), the way VS Code, Raycast and similar apps ship. Today the only install path is downloading the release artefact from GitHub by hand. Add a Homebrew cask for the Lovelace desktop app so installation, upgrades and uninstallation go through brew.

Since Lovelace is a GUI application distributed as a signed, notarised macOS bundle, this is a cask, not a formula.

## Requirements

- Create a Homebrew tap under the organisation (`lovelace-co/homebrew-tap`) holding a `lovelace` cask, so users run `brew tap lovelace-co/tap` then `brew install --cask lovelace`. Submission to the central `homebrew/cask` repository can come later once the app meets its notability bar; the tap works from day one.
- The cask points at the versioned release artefact on GitHub releases (the notarised `.dmg` or `.app` archive from the existing release pipeline) with its `sha256`, an `app` stanza installing into `/Applications`, and `auto_updates true` because the app already ships the Tauri updater.
- Both architectures are covered: either a universal artefact or per-architecture `arm64`/`intel` blocks with their own checksums, matching what the release pipeline actually produces.
- A `zap` stanza lists the app's leftovers (application support, caches, preferences) so `brew uninstall --zap` removes them; enumerate the real paths the app writes on macOS.
- Release automation keeps the cask current: when a release is published, CI updates the cask's `version` and `sha256` in the tap repository automatically. A stale cask that lags releases is a failed acceptance, not a nice-to-have.
- Installing over an existing manual install must not break: same bundle identifier and install location, so brew adopts or replaces cleanly.
- Document the install command in the readme alongside the direct download.

## Acceptance criteria

- On a clean macOS machine: `brew tap lovelace-co/tap && brew install --cask lovelace` installs the app into `/Applications`, it launches, passes Gatekeeper without warnings, and `brew uninstall --cask lovelace` removes it.
- `brew upgrade --cask lovelace` moves an older installed version to the latest release.
- Publishing a new release updates the cask in the tap without manual editing.
- `brew audit --cask lovelace` passes in the tap.

## Non-goals

- No Linux or Windows package managers in this ticket (apt, winget, Chocolatey and similar are separate work if wanted).
- No submission to the central `homebrew/cask` repository yet; the tap is the deliverable.
- No changes to how the app itself is built, signed or notarised; the cask consumes the existing release artefacts.
