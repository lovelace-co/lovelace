## Description

Commit 72fd60e (chore: update demo project with claude assets and sample ticket) added `examples/demo-project/.lovelace/tickets/T-0005.md` to the canonical fixture, but several tests still hard-code the expectation that the fixture holds four tickets (T-0001 to T-0004). The suite has been red on every branch since:

- `packages/core`: 9 failures across `test/index-gen.spec.ts` (entity count and sort), `test/mutate.spec.ts` (ID assignment scanning expects the next ID after T-0004; six cases) and `test/order.spec.ts` (board order empty-map case).
- `packages/mcp`: 2 failures, `test/host.spec.ts` (set_column_order) and `test/server.spec.ts` (the full agent loop expects a new ticket to be assigned T-0005 but gets T-0006).

Verified against clean HEAD (4b89b19) in a fresh worktree: the same 9 core failures reproduce with no working-tree changes, so this is baseline breakage, not caused by any in-flight work.

CLAUDE.md's rule is that the fixture stays valid and tests run against it; the fixture change was legitimate (T-0126/T-0127 needed a ticket with a body), so the fix is updating the test expectations to the five-ticket fixture, not reverting the fixture.

## Acceptance criteria

- [ ] `pnpm test` passes from the repo root with no failures in `packages/core` and `packages/mcp`.
- [ ] Test expectations derive from or match the current fixture contents; a comment near the counts notes that the fixture and these expectations move together.
- [ ] No change to the fixture itself beyond what validity requires.
