title: Release notes to be shown when you do update a schema version
---

When a project needs a major-version migration, the SpecGate screen (apps/desktop/src/components/SpecGate.tsx) currently shows only each migration step's terse one-line summary. Add release notes so the user sees what actually changed before committing to migrate.

Scope, confirmed with the user (session S-0119):
- Placement: enrich the existing pre-migration SpecGate screen only. No post-migration recap screen.
- Content: every SPEC.md changelog entry with version > the project's declared version and <= the migration's target version.
- Coverage: major-version migrations only. Same-major minor/patch bumps continue to open silently per ADR-0011; out of scope here.

Sourcing mechanism: SPEC.md's changelog stays hand-authored prose (SPEC.md:94-107). A structured copy (version + description) is compiled into packages/core as TS data, since the shipped app cannot read SPEC.md from disk at runtime (it operates on a user's project, not this repo). A test parses SPEC.md's changelog section and asserts it matches the TS data byte-for-byte, so the two can never silently drift.

Acceptance criteria:
- SpecGate renders release notes for a pending major migration, sourced from the new packages/core changelog data.
- A packages/core test fails if the changelog data and SPEC.md's changelog section ever diverge.
- pnpm test and pnpm build pass.
- No change to minor/patch silent-open behaviour, no new MCP tool, no post-migration screen, no change to MigrationStep.apply or any file-mutation logic.
