## Description

ID assignment trusts the counter files under .lovelace/state/counters/ without reconciling them against the files on disk, and createTicket and logSession write to the assigned path without checking it already exists. When the counter state is behind the ticket directory, the next create silently overwrites an existing entity file.

This is not hypothetical: it happened in this repository on 2026-07-21. A git pull brought in tickets T-0131 to T-0138 and sessions up to S-0135 from another machine, but the local (gitignored) counters still pointed at 131 and 122. The next create_ticket overwrote T-0131.md and the next log_session overwrote S-0122.md; a second attempt overwrote T-0132.md and S-0123.md. All four were recovered from git, but an untracked or uncommitted entity would have been lost outright. Any project synced across two machines can hit this.

It recurred on 2026-07-22: the T counter held 139 with T-0142 on disk and the S counter 135 with S-0138 on disk, so create_ticket reused T-0139 and overwrote the done ticket "Sign and notarise macOS release builds" (recovered from git; counters advanced by hand). Exact code points: `nextId()` trusts an existing counter at `packages/core/src/ids.ts:41` and only scans when the file is missing (`ids.ts:44`); `createTicket` writes unconditionally at `packages/core/src/mutate.ts:154` and `logSession` at `mutate.ts:647`. Comments already guard with a `while (existsSync(path))` loop at `mutate.ts:676`; tickets and sessions have no equivalent.

## Proposed fix

- On assignment, reconcile the counter with the highest existing ID for the prefix (max of counter and directory scan), as the state-deletion rescan already does.
- Open entity files for creation exclusively (O_EXCL semantics) so a collision fails loudly instead of overwriting; surface a clear validation error naming the file.

## Acceptance criteria

- [ ] With a counter behind the directory contents, create_ticket assigns the next unused ID rather than overwriting, for tickets and sessions.
- [ ] A forced path collision produces a clear error, never a silent overwrite.
- [ ] Tests cover the stale-counter case for tickets, sessions and comments, using the demo fixture plus a deliberately staled counter.
